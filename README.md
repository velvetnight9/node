# Установка и донастройка нод

Три самостоятельных установщика для Debian 12 и Ubuntu 24.04:

- `install-yandex-cdn.sh` — origin за Яндекс Cloud CDN.
- `install-timeweb-cdn.sh` — origin за Timeweb CDN.
- `install.sh` — обычная нода с маскировкой и опциональными компонентами.

Для новой CDN-ноды сначала создайте профиль и ноду в RemnaWave по HTML-гайду.
Порт управления в панели должен совпадать с `NODE_PORT` ноды. Это отдельный порт,
не SSH, не XHTTP и не публичный 443.
В HTML-гайдах CDN-скрипт заменяет ручные шаги установки ноды и origin (шаги 4–5).
Настройка самого ресурса CDN и выдача доступа в панели остаются отдельными шагами.

## Запуск

Скачайте нужный файл и запустите от root:

```bash
bash install-yandex-cdn.sh
# либо
bash install-timeweb-cdn.sh
```

Скрипт определит уже установленную ноду, nginx и XHTTP-порт. Недостающие данные
спросит в терминале. SECRET_KEY вводится скрыто только для новой ноды.
SSH-порт запрашивается отдельно (по умолчанию 48522), порт управления — отдельно
(по умолчанию 9744). Они не подменяют друг друга. Прежде чем менять NODE_PORT
существующей ноды, укажите этот же порт в её записи в панели.
IP панели — фактический исходящий адрес, с которого она подключается к ноде.
Несколько адресов можно указать через пробел; среди них обязателен IPv4 панели.
Подключайтесь к серверу по SSH через IPv4: установщик отключает IPv6.

```bash
PANEL_IPS="203.0.113.20 2001:db8::20" SSH_PORT=48522 NODE_PORT=9744 bash install-yandex-cdn.sh --repair
PANEL_IPS="203.0.113.20" SSH_PORT=48522 NODE_PORT=9744 bash install-timeweb-cdn.sh --security-only
bash install-yandex-cdn.sh --check
PANEL_IPS="203.0.113.20" SSH_PORT=48522 NODE_PORT=9744 bash install.sh --repair
```

Без флагов существующая обычная нода проходит безопасную донастройку, а не
переустановку. `install.sh --resume` явно продолжает незавершённую полную установку.
Не применяйте `--resume` для произвольной вручную настроенной машины.

## Что применяется

- UFW разрешает выбранный SSH-порт с любого IP и TCP 80/443. Управляющий порт доступен
  только указанным IP панели. Отдельный nftables guard закрывает обход через
  ранние UFW ACCEPT и опубликованный Docker controlport; чужие таблицы не очищаются.
- IPv6 отключается для всех существующих интерфейсов, включая loopback, и по
  умолчанию для новых. Настройки сохраняются в
  `/etc/sysctl.d/99-remnanode-network.conf`. При SSH через IPv6 или отсутствии
  IPv4 панели скрипт останавливается до изменения доступа.
- TCP BBR включается вместе с `net.core.default_qdisc=fq`; модули `tcp_bbr` и
  `sch_fq` загружаются сейчас и через `/etc/modules-load.d/remnanode-network.conf`
  при загрузке системы. Если BBR недоступен в текущем ядре, скрипт сообщает об
  ошибке. Ядро автоматически не заменяется. При ошибке применения sysctl
  выполняется возврат сохранённых значений, постоянные файлы сохраняются.
  Уже установленные очереди интерфейсов и явный шейпинг не заменяются;
  BBR применяется к новым TCP-соединениям. Механизм описан в
  [документации Linux](https://kernel.org/doc/html/latest/networking/ip-sysctl.html)
  и [руководстве BBR](https://github.com/google/bbr/blob/master/Documentation/bbr-quick-start.md).
- Публичные клиентские порты определяются по слушателям Xray от root
  (стандартный образ RemnaWave). Одного имени непривилегированного процесса
  для автоматического открытия порта недостаточно. Это
  включает ограниченный Telegram inbound на TCP/24443. Локальные 127.0.0.1/::1
  и внутренний API не открываются. Таймер раз в 30 секунд подхватывает новые
  inbound, поэтому они не требуют ручного исправления UFW после смены профиля.
  Для UDP дополнительно читается реальный конфиг работающего ядра, в том числе
  через внутренний Unix socket RemnaWave. Случайные исходящие UDP-сокеты не открываются.
- Обычная нода сохраняет UDP/443 для Hysteria. CDN-нода сохраняет его только при
  обнаруженном работающем UDP-транспорте. Старые общие разрешения 3000/3001
  удаляются, если порт не занят другим сервисом.
- Fail2ban защищает только фактические SSH-порты: 5 ошибок за 10 минут, бан 1 час.
  Панель, loopback и текущий IP администратора исключены из SSH-банов.
  nginx 400/403/404 не используются как повод забанить CDN edge.
- SSH переводится на выбранный порт, включая socket activation Ubuntu 24.04.
  Локальные X11-порты 6010/6011 не считаются входом по SSH; старые ошибочные
  разрешения удаляются. Старый SSH-порт закрывается после проверки нового listener.
  Вход только по ключу: PasswordAuthentication и keyboard-interactive отключены,
  AuthenticationMethods — publickey. Если текущий ключевой вход не подтверждён,
  скрипт запрашивает ваш публичный ключ; без него завершает установку с ошибкой.
  Свой ключ можно заранее передать через `SSH_PUBLIC_KEY`. Приватный ключ не нужен.
  Окружение SSH восстанавливается после sudo без печати остальных переменных.
- Действующие ключ и домены сохраняются. При смене NODE_PORT меняется только
  environment соответствующего сервиса в compose и пересоздаётся только нода,
  с тем же образом и SECRET_KEY. Для bridge-сети автоматическая смена порта
  отклоняется, поскольку нужно отдельно проверить published ports. Нода не обновляется
  на новый образ автоматически. В новой установке журнал контейнера ограничен
  20 МБ × 3; изменение логирования существующего контейнера требует отдельного
  пересоздания и не выполняется незаметно.
- CDN-скрипт исправляет несовпадение nginx/Xray, включая случай 4443 → 7443.
  Если конфиг содержит несколько upstream, скрипт останавливается для ручного
  выбора, не переписывая соседние сайты.
- В системном nginx лимиты повышаются как минимум до 8192 соединений на worker
  и 65535 файловых дескрипторов; большие действующие значения сохраняются.
  Лимиты существующего Docker nginx остаются в его compose и основном конфиге.
- Для CDN не включаются traffic-guard, Psiphon и ограничение скорости по IP.
  В новой обычной ноде шейпинг по умолчанию выключен; его можно включить явно.

Копии настроек сохраняются в закрытый `/root/remnanode-security-*`.
При ошибке применения файрвола возвращаются предыдущие UFW и control guard.
Ремонт nginx сохраняет копию и проверяет `nginx -t` до reload.

## Границы автоматизации

CDN-ресурс, DNS, сертификат домена CDN и Host/SNI в панели настраиваются по гайду.
Скрипт не меняет аккаунт провайдера и профили других нод. Проверка origin 400/404
не заменяет подключение клиента через публичный CDN и проверку upload/download.
Внешние security groups хостинга и сторонние firewall-сервисы могут накладывать
дополнительные ограничения. Не запускайте два установщика одновременно.

## Исходники и проверки

`build.py` встраивает общую часть `src/security.sh` в каждый файл; отдельная
библиотека на устанавливаемой машине не нужна. `src/standard-base.sh` — снимок
основного установщика до обновления безопасности.

```bash
python3 build.py
python3 tests/check_sources.py
python3 tests/check_network.py
```

IPv6/BBR применяются при новой установке, `--repair`, обычной донастройке
существующей ноды и CDN `--security-only`. Для уже установленной ноды скачайте
обновлённый скрипт и запустите `--repair`; обновление файла на GitHub само по себе
не меняет настройки работающих серверов. `--check` ничего не применяет.
`tests/check_network.py` проверяет sysctl в изоляции с подменой системных команд.

`tests/linux-security.sh` выполняется только в одноразовой Linux QA VM с systemd,
правами на nftables и network namespaces. На production этот тест запускать нельзя.

## Исходный архив страницы

`index_zaglushka.zip` остаётся архивом статической страницы, а не установщиком. Перед публикацией страницы проверьте HTML, assets и внешние ссылки; не заменяйте её примером общий nginx/Caddy config. Секреты и данные частной инфраструктуры в репозиторий не добавляются.
